# Troubleshooting

Symptoms the CLI does not explain. For anything else, the error text and
`rive docs gotchas` come first.

| Symptom | Cause | Fix |
|---|---|---|
| A headless `--screenshot` is blank or one flat colour, but the live window looks right | The work needs several draws (chunked bake, deferred GPU setup), and a headless capture draws once. `--advance` does not draw. | Use the live window's `screenshot <path>`, or a throwaway copy that does all the work in the first draw. |
| `key: nothing is focused` after a `--pointer` click | A headless click never gives focus, even with `canTouch`. | Put a `FocusActionTarget` in the entry state, `--advance` a frame or two, then send `--key`. |
| A button works with a mouse but not with a finger in the web build (seen in a showcase game's start button, November 2026) | On `touchend` the web runtime calls pointer up, then pointer exit, then advances (in the code of web runtimes 2.43.1, 2.45.0 and 2.49.3 and current source; reproduced on 2.45.0 and 2.49.3). An exit that clears hover, pressed or armed state runs before the script's next advance, so a commit gated on that state is lost. A mouse release sends no exit, and the native CLI does not pass this exit to a script's `pointerExit`, so only the web build shows it. `dispatchPointerExit` covers only `mouseout`. | Commit in the Click listener or the `pointerUp` handler, and use exit only to cancel a press not yet released. Tap every menu control of the signed build with real touch events (CDP `Input.dispatchTouchEvent`), not mouse events. |
| A pad works in the CLI but does nothing in the web build | The web runtime is not reading pads for that canvas: the runtime is too old to read them, a page option switches them off, or pads wait for the canvas to have focus. | Check the runtime version and the page's options against "Gamepad input" in [workflows.md](workflows.md). |
| A 3D or shader layer is missing in a web page | GPU Canvas is opt-in per runtime instance and off by default (`@rive-app/webgl2` 2.42.0+). Without it, a layer drawn through it never appears (seen on 2.45.0 and 2.49.3). Layer Masks need it too. | Pass `enableGPUCanvas: true` for the files that need it. If you construct a `RiveFile` yourself, set it there: the file's flag wins. Keep it per file: each instance takes its own WebGL context, browsers cap them, and Rive calls the API experimental. |
| `@rive-app/webgl2-threads` runs without threads: script audio processors fail as they start, jobs run on the page thread | The package (2.47.0+) loaded its build without threads and logged `Rive is running without threads: <reason>`. The reason is most often that the page is not cross-origin isolated. It can also be a page that cannot share memory with workers, a browser without wasm threads and SIMD, or a threaded build that failed to load. | Read the logged reason. For isolation, serve the page with `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`, as Rive's hosted pages do, and check that `crossOriginIsolated` is true. Isolation covers the whole document, so check every third-party script and frame on it. Once threads load, GPU Canvas instances replay their frames on a worker by default (2.49.0+, experimental), and that left one showcase file blank. Test each file with it, and turn it off with `RuntimeLoader.setReplayWorker(false)` before the runtime loads, or `useReplayWorker: false` per instance. |
| The web build logs `execution exceeded … timeout`, then `require could not find a script named …` or `wasm call trapped in host_obj_user_init`, or stays blank, sometimes only on phones | A setup call (`init` or a Luau module's top level) ran past its time budget. Slow devices hit it first, and from web runtime 2.48.0 Luau module top levels have a budget too. | Move the work out of setup. See "Script time budgets" in [optimisation.md](optimisation.md). |
| Native `--data` captures look right, but the browser ignores host writes | `--data` lands before the first advance, so the path for later writes never ran. Once `advance` returns `false` Rive stops calling it, so it cannot poll. | Register `addListener` on each property you draw from and call `context:markNeedsUpdate()`. Prove it in the signed browser run. |
| `Unknown require: name` for a script that exists | The script is a symlink, so its module name is the target's path. | Copy the file. For declaration order and `isModule`, see `rive docs luau/protocols`. |
| `Key 'image' not found in external type 'GPUTarget'` (1.3+) | `GPUCanvas` became `GPUTarget & {…}`, and the checker narrows a `self.canvas` field read to `GPUTarget`. | Read it once into a local at the top of `draw` (`local canvas = self.canvas`), or cast with `(self.canvas :: GPUCanvas).image`. |
| `push`, `pull` or `library publish` stops with "Rerun with --yes" | 1.5.0+ asks before overwriting, and an agent shell cannot answer. | Add `--yes` after confirming the target file is the right one. |
| A scripted `.riv` plays nothing in a web page | It was built unsigned (`--once`, watch, or a copied `build/` file), or the page reads frames during the splash. | Build with `--publish`, and gate the reveal on a script-set "drawn" flag plus a pixel check. |
| The signed file is still watermarked after binding | The publish service decides, probably by workspace plan; this is not a CLI fault. | Record it, hide the canvas during the splash, and do not strip the watermark. |
| `--test` is green but nothing ran | No script returns the Tests protocol (`noTestsFound: true`). | Gate on `noTestsFound == false` and on named cases. |
| `--verify` fails on a fresh clone with missing asset files | Generated inputs (audio, RML) have not been produced yet. | Run the project's prepare/generator step first. |
| The live window ignores terminal commands, or `pkill -f rive` kills your own shell | stdin is closed, or `-f` matched the calling shell's command line. | Keep stdin open (`tail -f /dev/null \| rive <dir>`, or a pty) and stop it with `pkill -x rive`. |
| Captures differ from the export on Linux/Mesa | A capture-only `LD_PRELOAD` shim (GLSL fixes, frame grabs) leaked into the build. | Unset preloads for `--once`, `--publish` and `--verify`, and set them only for capture runs. |
